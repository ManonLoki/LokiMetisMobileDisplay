# 01 文件结构

> 上一篇：[文档索引](README.md) ｜ 下一篇：[02 技术架构](02-技术架构.md)

本仓库是一个 Kotlin Multiplatform 工程，但 Apple 端（iPhone、iPad、Apple Watch、小组件）的界面和网络完全用 Swift 原生实现，只在少数地方借用 Kotlin 的共享校验。配对、认证和加解密的核心逻辑在**桌面仓库**的 Rust 代码里，构建时编译成静态库链入手机 App。

## 顶层目录

```
LokiMetrisDisplay/
├── iosApp/            Apple 端 Xcode 工程：iPhone/iPad App、Watch App、小组件
├── appleDisplay/      Apple 端共享 Swift 源码（SwiftPM 包），App/Watch/小组件直接编译同一份文件，并在 macOS 上跑单元测试
├── sharedLogic/       Kotlin 共享逻辑：协议常量、名称校验、展示模型；Android 端的网络引擎也在这里
├── sharedUI/          Kotlin Compose 共享界面（Android 使用）
├── androidApp/        Android 宿主：Activity、前台服务、桌面小组件、悬浮窗、后台调度
├── scripts/           构建脚本：编译 Rust 移动桥、生成各端图标、准备 Android 签名
├── branding/          图标母版 app-icon.png
├── signing/           Android 固定签名（私钥与密码被 Git 忽略）
├── docs/              本组中文文档
└── README.md          安装、启动调试、能力、设备与架构入口
```

**为什么 Apple 端不用 Compose？** 小组件和 Watch 只能用 SwiftUI；手机端也要用 WatchConnectivity、BackgroundTasks、WidgetKit、Keychain 等系统能力。所以选择“Apple 全原生 + 共享 Swift 包”的结构，详见 [02 技术架构 · 为什么这样分层](02-技术架构.md#为什么这样分层)。

## iosApp/：Apple 端工程

```
iosApp/
├── iosApp.xcodeproj         一个工程三个 target：iosApp、LokiMetrisWatch、LokiMetrisWidgets；主 App 内含 Kotlin/Rust 构建脚本阶段
├── Configuration/Config.xcconfig   版本号、团队 ID、Bundle ID、App Group 统一在这里配置
├── AppLocalization/         应用显示名的本地化（中文“诡秘神谕”，其他语言“LokiMetris”）
├── iosApp/                  iPhone / iPad 主 App
├── LokiMetrisWatch/         Apple Watch App
├── LokiMetrisWidgets/       桌面与锁屏小组件扩展
└── WidgetShared/            App 与小组件共用的 App Group 访问入口
```

### iosApp/iosApp：iPhone／iPad 主 App

按“入口 → 状态模型 → 网络引擎 → 存储 → 界面”的顺序：

| 文件 | 职责 |
| --- | --- |
| `iOSApp.swift` | App 入口。创建唯一的设置对象与连接模型，按 App 级前后台切换启停连接，进入后台时申请下一次后台刷新 |
| `LanLinkModel.swift` | 主线程薄模型：把网络引擎投递的状态赋给 `@Published state`，把界面操作转发给引擎 |
| `LanLinkEngine.swift` | **网络 owner**：发现、配对、认证、心跳、后台刷新都在它的串行队列上；定义发布给界面的 `LanLinkView` |
| `LanLinkEngine+Connection.swift` | 引擎扩展：Bonjour 浏览、选择桌面、配对握手、认证、重试与超时 |
| `LanLinkEngine+Display.swift` | 引擎扩展：接收快照、逐块下载图片、图片解码调度、同步给 Watch、冷启动恢复缓存 |
| `NativeLinkBridge.swift` | Rust 移动桥的 Swift 包装：一个句柄承载配对窗口与加密会话；图片完整性校验 |
| `MobileBridge.h` | Rust 桥的 C 头文件（桥接头） |
| `PairingStore.swift` | 配对秘密的 Keychain 存取（仅本机、首次解锁后可读、不同步） |
| `DeviceIdentityStore.swift` | 本机设备 UUID 的 Keychain 存取；从已有配对记录选择唯一合法身份 |
| `DeviceSettings.swift` | 设备名称与身份的主线程状态 |
| `BackgroundTargetStore.swift` | 记录“最近成功认证的桌面”的 Bonjour 服务名，供后台刷新重新解析地址（不存 IP 与秘密） |
| `BackgroundRefreshScheduler.swift` | `BGAppRefreshTask` 注册与执行，保证系统完成回调只调用一次 |
| `IOSAssetCache.swift` | 图片内容寻址缓存（`lan-assets-v1`）：分块写入、完整校验、原子提交、512MiB 收敛 |
| `IOSDisplayCache.swift` | 给 Watch 传图时只读查找已落盘图片，并记住已校验过的文件，避免重复整文件哈希 |
| `PhoneWatchBridge.swift` | **Watch 通道 owner**：WCSession、逐块 RPC、HTTP 配置下发、离线缓存答复 |
| `WidgetSnapshotPublisher.swift` | 把认证快照写入 App Group 并通知小组件刷新；合并积压写入，30 秒节流 |
| `ContentView.swift` | 顶层导航（手机底部标签、iPad 侧栏）与设置页 |
| `LanDisplayPage.swift` | 展示台：用量卡片、Hooks 卡片、详情弹层；定义 App 配色 |
| `HookAssetImage.swift` | 动图播放视图，iPhone 与 Watch 共用；只在可见且允许动效时按帧间隔唤醒 |
| `CyberMotion.swift` | 赛博风格的背景、卡片扫光、入场动画与按压反馈，统一受动效开关控制 |
| `PanelPreferences.swift` | 面板显示偏好（精简／详细、1×1／2×2 等）及其设置页 |

### iosApp/LokiMetrisWatch：Apple Watch App

| 文件 | 职责 |
| --- | --- |
| `LokiMetrisWatchApp.swift` | 入口、后台任务处理（`WKApplicationDelegate`）、三页界面（Hooks／Token／额度） |
| `WatchProviderQuotaContent.swift` | 额度页：账户名称、套餐 Tag 与各时间窗口的剩余额度；大字号时纵向排列窗口 |
| `WatchLinkEngine.swift` | **Watch owner**：接收 iPhone 的分块数据、本机缓存、图片解码、HTTP 后备、后台刷新窗口 |
| `WatchHTTPConfigurationStore.swift` | 把 iPhone 下发的只读 HTTP 配置存进 Watch 本机 Keychain |

Watch 不链接 Kotlin 和 Rust，也不自己做 Bonjour 发现。

### iosApp/LokiMetrisWidgets 与 WidgetShared

| 文件 | 职责 |
| --- | --- |
| `LokiMetrisWidgets.swift` | 小组件 Timeline 与五种尺寸的视图（桌面小／中、锁屏单行／圆形／矩形） |
| `WidgetShared/WidgetContainer.swift` | 定位 App Group 容器；执行一次 HTTP 刷新并记录诊断结果 |

## appleDisplay/：Apple 端共享 Swift 包

这是一个零第三方依赖的 SwiftPM 包。**它不是被当作库链接的**，而是由 Xcode 工程把同一批源文件分别编进 App、Watch、小组件三个 target；SwiftPM 只用来在 macOS 上快速跑测试（`swift test --package-path appleDisplay`）。

按主题分组：

| 主题 | 文件 | 说明 |
| --- | --- | --- |
| 通用 | `SharedSupport.swift` | UUID／摘要格式校验、SHA-256、共享 JSON 编解码器、安全删除文件 |
| 局域网 | `LanSocket.swift`、`LanFrames.swift` | TCP 连接与长度前缀分帧；写队列有界、半写超时即关闭 |
| | `LanConnectionPolicy.swift` | 前台自动发现与最多 8 次退避重试；设备形态上报 |
| | `LanProjectionDelivery.swift` | 后台队列 → 主线程“只投递最新值”的合并器 |
| 展示数据 | `LanDisplaySnapshot.swift` | 完整快照的解析与校验（Token、Hooks、图片清单、额度） |
| | `LanImageAsset.swift` | 图片（含 GIF／APNG／WebP 动图）有界解码与播放时钟 |
| | `LanAssetFiles.swift` | 启动时清理上次崩溃留下的半成品文件 |
| | `WidgetSnapshot.swift` | 小组件摘要格式、45 秒租约、数字格式化、额度排序 |
| | `ProviderPlanBadge.swift` | App、Watch 与小组件共用的账户名称与套餐 Tag 样式 |
| 共享存储 | `WidgetSnapshotStore.swift` | App Group 内的摘要、完整展示缓存、只读刷新目标；跨进程文件锁 |
| HTTP | `WidgetRefreshTarget.swift`、`WidgetHTTPClient.swift` | 只读 HTTP 目标与加密请求客户端（6 秒总期限、拒绝重定向） |
| Watch | `WatchProtocol.swift` | iPhone↔Watch 的 RPC 格式、分块传输策略、前台租约、通信事实 |
| | `WatchDisplayStore.swift` | Watch 本机展示缓存（v2）与 5 分钟刷新策略 |
| | `WatchAssetCache.swift` | Watch 图片缓存：流式校验、256 像素解码 |
| | `WatchHTTPConfiguration.swift` | iPhone 下发给 Watch 的只读配置及修订号规则 |
| 身份 | `DeviceIdentityPolicy.swift` | 设备身份选择策略 |

`appleDisplay/Tests/AppleDisplayTests/` 下每个测试文件对应一个主题，例如 `WatchTransferTests` 覆盖分块传输与缓存优先级，`PhoneHookCacheTests` 覆盖插槽图片缓存的时间规则。

## Kotlin 与 Android 部分

| 目录 | 说明 |
| --- | --- |
| `sharedLogic/src/commonMain` | 协议与模型：`MdnsProtocol`（服务类型、设备名校验，iOS 也调用）、`TerminalTransport`（分帧与重试策略）、`TerminalDisplay`（展示投影）、`ProviderQuota`、`PanelConfiguration` 等 |
| `sharedLogic/src/androidMain` | Android 网络引擎 `AndroidLanEngine`、NSD 发现、Keystore 配对存储、小组件存储与 HTTP |
| `sharedUI/src/commonMain` | Compose 界面：展示台、设置页、用量卡片、动效 |
| `androidApp/` | `DisplayApplication`（应用级 owner）、`MainActivity`、`AndroidDisplayService`（后台实时同步前台服务）、`MetrisWidgetProvider`（桌面小组件）、悬浮窗、`JobScheduler` 调度 |

## 构建链路

```
Xcode 构建 iosApp
 ├─ 脚本阶段 1：scripts/build_mobile_native.py --desktop-root <桌面仓库>    → Rust 静态库（按真机／模拟器分别编译）
 ├─ 脚本阶段 2：./gradlew :sharedLogic:embedAndSignAppleFrameworkForXcode   → SharedLogic.framework
 ├─ 编译 iosApp/iosApp/*.swift + appleDisplay/Sources/**/*.swift
 ├─ 嵌入 LokiMetrisWatch（只编译 Swift，不依赖 Kotlin/Rust）
 └─ 嵌入 LokiMetrisWidgets（只编译 Swift）
```

- 桌面仓库路径默认是相对路径，可用 Xcode 设置 `LOKI_DESKTOP_ROOT` 覆盖。
- 当前脚本把 iOS Rust 桥输出到 `iosApp/build/native/<SDK>/`，Android 桥输出到 `androidApp/build/generated/mobileNative/jniLibs/<ABI>/`；Rust 中间产物放在 `build/mobile-native/rust/`。
- Apple 各目标版本在 `iosApp/Configuration/Config.xcconfig`（`MARKETING_VERSION`、`CURRENT_PROJECT_VERSION`）配置；Android 版本在 `androidApp/build.gradle.kts` 配置。

常用命令：

```sh
swift test --package-path appleDisplay                       # Apple 共享逻辑单元测试
xcodebuild -project iosApp/iosApp.xcodeproj -scheme LokiMetrisWatch -configuration Debug \
  -sdk watchsimulator -destination 'generic/platform=watchOS Simulator' CODE_SIGNING_ALLOWED=NO build
xcodebuild -project iosApp/iosApp.xcodeproj -scheme iosApp -configuration Debug \
  -destination 'generic/platform=iOS Simulator' \
  LOKI_DESKTOP_ROOT=/absolute/path/to/LokiMetis CODE_SIGNING_ALLOWED=NO build
./gradlew :androidApp:assembleDebug -PlokiDesktopRoot=/absolute/path/to/LokiMetis
```

把示例中的桌面仓库路径替换为本机路径；完整的工具、签名和运行步骤见 [项目 README](../README.md#从源码启动调试)。图标母版是 `branding/app-icon.png`，在 macOS 仓库根目录执行 `swift scripts/generate_app_icons.swift` 可重新生成各端图标，只使用系统 SDK。

## 运行时文件布局（设备上）

知道数据落在哪里，排查缓存问题会快很多：

| 位置 | 内容 | 谁写 |
| --- | --- | --- |
| iPhone Keychain `…lan-identity-v1` | 本机设备 UUID | `DeviceIdentityStore` |
| iPhone Keychain `…lan-pairing-v1` | 每台桌面一条配对秘密，账户名为「桌面UUID.本机UUID」 | `PairingStore` |
| iPhone Keychain `LokiMetris.watch-http-revision.v1` | 下发给 Watch 的配置修订号（只增不减） | `PhoneWatchBridge` |
| iPhone `Application Support/lan-assets-v1/` | 按 SHA-256 命名的图片原文件 | `IOSAssetCache` |
| iPhone `Application Support/BackgroundRefresh/<本机UUID>.json` | 后台刷新目标（Bonjour 服务名） | `BackgroundTargetStore` |
| App Group `display-widget-v1.json` | 小组件摘要（含 45 秒租约） | App、小组件 |
| App Group `display-phone-v1.json` | 完整展示缓存（含图片清单，不含图片字节） | App、小组件 |
| App Group `display-widget-refresh-v1.json` | 只读 HTTP 目标 | App |
| App Group `Library/Caches/WidgetRefresh/*.json` | 每次 HTTP 刷新的诊断结果（不含地址与密钥） | 小组件、App 调试探针 |
| Watch `Application Support/WatchLink/` | 身份文件、`watch-display-v2.json` 展示缓存、`assets/` 图片 | `WatchLinkEngine` |
| Watch Keychain | 只读 HTTP 配置 | `WatchHTTPConfigurationStore` |

数据为什么这样分放、谁能读谁，见 [02 技术架构 · 存储与安全边界](02-技术架构.md#存储与安全边界)。
