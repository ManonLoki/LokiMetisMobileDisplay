# 01 文件结构

> 上一篇：[文档索引](README.md) ｜ 下一篇：[02 技术架构](02-技术架构.md)

本仓库采用 Kotlin Multiplatform（KMP，跨平台共享 Kotlin 代码）共享业务规则，Android 使用 Compose 界面，Apple 使用原生 SwiftUI 界面。`SharedLogic` 已供 Android、iPhone／iPad、Watch 与 iOS 小组件调用，业务规则包括展示与额度、模型校验、面板布局、连接阶段与期限、帧容量与写队列、能力协商、图片缓存与解码预算、只读 HTTP 边界、缓存接纳、租约、身份恢复及 Watch 通信与配置；各端网络、系统存储与生命周期仍由平台代码管理。配对、认证和主连接加解密的核心逻辑在**桌面仓库**的 Rust 代码里，分别链入 Android 和 iPhone／iPad 主 App，Watch 与小组件不链接该 Rust 桥。

## 顶层目录

```
LokiMetrisDisplay/
├── iosApp/            Apple 端 Xcode 工程：iPhone/iPad App、Watch App、小组件
├── appleDisplay/      Apple 端共享 Swift 源码；各 target 源码共编并链接 SharedLogic，SwiftPM 用 macOS 框架测试
├── sharedLogic/       KMP 共享规则与模型；androidMain 放 Android 网络、存储与原生桥接实现
├── androidApp/        Android 应用：Compose 页面、Activity、前台服务、桌面小组件、悬浮窗、后台调度
├── scripts/           构建与测试脚本：Apple SharedLogic、Rust 移动桥、各端图标、Android 签名
├── branding/          图标母版 app-icon.png
├── signing/           Android 固定签名（私钥与密码被 Git 忽略）
├── docs/              本组中文文档
└── README.md          安装、启动调试、能力、设备与架构入口
```

**为什么 Apple 端保留原生界面？** 当前手机、Watch 与小组件均已采用 SwiftUI，并使用 WatchConnectivity、BackgroundTasks、WidgetKit、Keychain 等系统能力。KMP 通过 Kotlin/Native（把 Kotlin 编译为平台原生代码）提供共享业务；`appleDisplay` 保留 Swift 的 Codable 数据编解码和平台适配。详见 [02 技术架构 · 为什么这样分层](02-技术架构.md#为什么这样分层)。

## iosApp/：Apple 端工程

```
iosApp/
├── iosApp.xcodeproj         三个 target 均链接 SharedLogic；只有主 App 构建和链接 Rust 桥
├── Configuration/Config.xcconfig   版本号、团队 ID、Bundle ID、App Group 统一在这里配置
├── AppLocalization/         应用显示名的本地化（中文“诡秘神谕”，其他语言“LokiMetris”）
├── iosApp/                  iPhone / iPad 主 App
├── LokiMetrisWatch/         Apple Watch App
├── LokiMetrisWidgets/       桌面与锁屏小组件扩展
└── WidgetShared/            App 与小组件共用的 App Group 访问入口
```

### iosApp/iosApp：iPhone／iPad 主 App

按“入口 → 状态模型 → 网络引擎 → 存储 → 界面”的顺序：

| 文件 | 职责 |
| --- | --- |
| `iOSApp.swift` | App 入口。创建唯一的设置对象与连接模型，按 App 级前后台切换启停连接，进入后台时申请下一次后台刷新 |
| `LanLinkModel.swift` | 主线程薄模型：把网络引擎投递的状态赋给 `@Published state`，把界面操作转发给引擎 |
| `LanLinkEngine.swift` | **网络 owner**：发现、配对、认证、心跳、后台刷新都在它的串行队列上；定义发布给界面的 `LanLinkView` |
| `LanLinkEngine+Connection.swift` | 引擎扩展：Bonjour 浏览、选择桌面、配对握手、认证、重试与超时 |
| `LanLinkEngine+Display.swift` | 引擎扩展：接收快照、逐块下载图片、图片解码调度、同步给 Watch、冷启动恢复缓存 |
| `NativeLinkBridge.swift` | Rust 移动桥的 Swift 包装：一个句柄承载配对窗口与加密会话；图片完整性校验 |
| `MobileBridge.h` | Rust 桥的 C 头文件（桥接头） |
| `PairingStore.swift` | 配对秘密的 Keychain 存取（仅本机、首次解锁后可读、不同步） |
| `DeviceIdentityStore.swift` | 本机设备 UUID 的 Keychain 存取；从已有配对记录选择唯一合法身份 |
| `DeviceSettings.swift` | 设备名称与身份的主线程状态 |
| `BackgroundTargetStore.swift` | 记录“最近成功认证的桌面”的 Bonjour 服务名，供后台刷新重新解析地址（不存 IP 与秘密） |
| `BackgroundRefreshScheduler.swift` | `BGAppRefreshTask` 注册与执行，保证系统完成回调只调用一次 |
| `IOSAssetCache.swift` | 图片内容寻址缓存（`lan-assets-v1`）：分块写入、完整校验、原子提交、512MiB 收敛 |
| `IOSDisplayCache.swift` | 给 Watch 传图时只读查找已落盘图片，并记住已校验过的文件，避免重复整文件哈希 |
| `PhoneWatchBridge.swift` | **Watch 通道 owner**：WCSession、逐块 RPC、HTTP 配置下发、离线缓存答复 |
| `WidgetSnapshotPublisher.swift` | 把认证快照写入 App Group 并通知小组件刷新；合并积压写入，30 秒节流 |
| `ContentView.swift` | 顶层导航（手机底部标签、iPad 侧栏）与设置页 |
| `LanDisplayPage.swift` | 展示台：用量卡片、Hooks 卡片、详情弹层；定义 App 配色 |
| `HookAssetImage.swift` | 动图播放视图，iPhone 与 Watch 共用；只在可见且允许动效时按帧间隔唤醒 |
| `CyberMotion.swift` | 赛博风格的背景、卡片扫光、入场动画与按压反馈，统一受动效开关控制 |
| `PanelPreferences.swift` | SwiftUI 设置与共享配置的薄适配；选项、默认值、列数、每页数量和分页位置来自 Kotlin |

### iosApp/LokiMetrisWatch：Apple Watch App

| 文件 | 职责 |
| --- | --- |
| `LokiMetrisWatchApp.swift` | 入口、后台任务处理（`WKApplicationDelegate`）、三页界面（Hooks／Token／额度） |
| `WatchProviderQuotaContent.swift` | 额度页：账户名称、套餐 Tag 与各时间窗口的剩余额度；大字号时纵向排列窗口 |
| `WatchLinkEngine.swift` | **Watch owner**：接收 iPhone 的分块数据、本机缓存、图片解码、HTTP 后备、后台刷新窗口 |

## appleDisplay/：Apple 端共享 Swift 包

Xcode 工程把各 target 所需的共享 Swift 源文件直接编进 App、Watch、小组件，并分别链接相应平台的 `SharedLogic.framework`。SwiftPM（Swift 包管理工具）测试也实际链接本项目的 macOS Kotlin 框架，不使用 Swift 算法替身。统一测试入口为 `python3 scripts/test_apple_shared.py`，它先构建当前 `macosArm64` 框架再执行 Swift 测试；需要 Apple Silicon macOS。

按主题分组：

| 主题 | 文件 | 说明 |
| --- | --- | --- |
| 通用 | `SharedSupport.swift` | UUID、文本与摘要格式校验转交 Kotlin；SHA-256、JSON 编解码器和文件访问保留系统实现 |
| 局域网 | `LanSocket.swift`、`LanFrames.swift` | Network.framework 连接与原生 Data 缓冲；帧容量、长度和写队列预算调用 Kotlin，实际收发与关闭由 Swift 执行 |
| | `LanDeviceFormFactor.swift` | UIKit 观察到的手机／平板类别；自动连接、退避与单连接形态上报规则在 KMP 中 |
| | `LanProjectionDelivery.swift` | 后台队列 → 主线程“只投递最新值”的合并器 |
| 展示数据 | `LanDisplaySnapshot.swift` | 完整快照的 Swift Codable 映射，Token、Hooks、图片清单与额度校验委托共享模型 |
| | `LanImageAsset.swift` | ImageIO 解码与播放时钟；像素、帧数、逐帧内存及缩边判断调用共享规则 |
| | `LanAssetFiles.swift` | 启动时清理上次崩溃留下的半成品文件 |
| | `WidgetSnapshot.swift` | 摘要的 Codable 映射；租约、Token、额度、Agent 别名／筛选／排序／合并与 Cursor 默认零行调用 Kotlin |
| | `ProviderPlanBadge.swift` | App、Watch 与小组件共用的账户名称与套餐 Tag 样式 |
| 共享存储 | `WidgetSnapshotStore.swift` | App Group 文件事务与跨进程锁；来源、时间、完整度与旧 HTTP 接纳规则调用 Kotlin |
| HTTP | `WidgetRefreshTarget.swift`、`WidgetHTTPClient.swift` | URL、JSON、系统网络与加密执行；路径、6 秒总期限、响应容量、重定向、Base64 和认证元信息边界调用共享规则 |
| Watch | `WatchProtocol.swift` | 保留 iPhone↔Watch 的 Codable 格式、Data 组装和系统计时器；前台租约、ACK 事实、传输选择、RPC 与分块边界调用 Kotlin |
| | `WatchDisplayStore.swift` | Watch 本机展示缓存（v2）；是否需要刷新由共享规则判断，系统调度预算仍由 watchOS 适配 |
| | `WatchAssetCache.swift` | Watch 图片缓存：流式校验、256 像素解码 |
| | `WatchHTTPConfiguration.swift` | 只读配置的 Codable 与系统类型映射；修订号、撤销、去重和缓存保留决策调用 Kotlin |
| 身份 | `DeviceIdentityPolicy.swift` | Keychain 读取与错误适配；配对账户索引恢复唯一设备身份的规则来自 Kotlin |

`appleDisplay/Tests/AppleDisplayTests/` 下每个测试文件对应一个主题，例如 `WatchTransferTests` 覆盖分块传输与缓存优先级，`PhoneHookCacheTests` 覆盖插槽图片缓存的时间规则。

Gradle 只保留 `androidApp` 与 `sharedLogic` 两个模块，依赖方向为 `androidApp → sharedLogic`。原 `sharedUI` 只配置 Android 目标，其页面已合入 `androidApp`；当前没有独立的跨平台 UI 模块。

这轮按职责整理**文件目录**，Kotlin 的 `package com.manonloki.lokimetrisdisplay` 保持原样，在用 JNI 入口与 Swift 类型名不随目录改变。目录用于定位职责，尚未通过不同包名建立访问边界；平台代码不能放入 `commonMain`。

合并后的 `ui/CyberMotion.kt` 负责 Compose 绘制与动画，`ui/platform/AndroidCyberMotion.kt` 负责系统动画设置与生命周期监听；`AndroidHookImage.kt` 负责 Android 图片视图的绑定、暂停与释放。这些文件都有实际平台职责。`App` 继续接收应用 owner 提供的图片和权限动作，页面不直接取得连接 owner。

展示入口统一为 `UsageDisplayPolicy` 与快照的 `displayUsageRows`；已移除无人调用的顶层转发、测试专用旧展示入口与初始测试模板。Swift 保留 Codable 外壳及有实际调用的 UI／错误适配，测试直接覆盖共享策略或生产行投影。设备类别文件从 `LanConnectionPolicy.swift` 改为 `LanDeviceFormFactor.swift`，Xcode 引用随之更新。

共享帧规则不要求共享字节容器：Android 仍持有 ByteBuffer／ByteArray，Apple 仍持有 Data，避免为容量判断引入大块跨语言复制。Swift 继续负责 JSON、Data、系统加密、文件和网络输入输出（I/O）；共享层只接收判断需要的字段或不可变状态。

`sharedLogic/build.gradle.kts` 声明 Android、iOS 真机／arm64 模拟器、watchOS arm64_32 与 arm64 真机／arm64 模拟器，以及用于本机测试的 `macosArm64` 目标。共享规则测试位于 `sharedLogic/src/commonTest`，Android 存储与编解码测试位于 `sharedLogic/src/androidHostTest`；Apple SwiftPM 测试通过真实 Kotlin 框架覆盖 Swift 适配与文件事务。

## 构建链路

```
Xcode 构建 iosApp / LokiMetrisWatch / LokiMetrisWidgets
 ├─ 各 target：python3 scripts/build_apple_shared.py
 │   └─ 带进程锁调用 Gradle，按当前 SDK／架构生成并链接 SharedLogic.framework
 ├─ 主 App：scripts/build_mobile_native.py --desktop-root <桌面仓库> → Rust 静态库
 ├─ 各 target：编译本身 Swift 文件 + appleDisplay 所需共享源码
 └─ 主 App 归档时嵌入 Watch App 与 Widget 扩展

macOS 测试：python3 scripts/test_apple_shared.py
 └─ 带同一把锁构建 macosArm64 SharedLogic，再执行链接该框架的 swift test
```

- 桌面仓库路径默认是相对路径，可用 Xcode 设置 `LOKI_DESKTOP_ROOT` 覆盖。
- 当前脚本把 iOS Rust 桥输出到 `iosApp/build/native/<SDK>/`，Android 桥输出到 `androidApp/build/generated/mobileNative/jniLibs/<ABI>/`；Rust 中间产物放在 `build/mobile-native/rust/`。
- Apple 各目标版本在 `iosApp/Configuration/Config.xcconfig`（`MARKETING_VERSION`、`CURRENT_PROJECT_VERSION`）配置；Android 版本在 `androidApp/build.gradle.kts` 配置。

常用命令：

```sh
python3 scripts/test_apple_shared.py                         # 先构建 macOS Kotlin 框架，再跑 Swift 测试
xcodebuild -project iosApp/iosApp.xcodeproj -scheme LokiMetrisWatch -configuration Debug \
  -sdk watchsimulator -destination 'generic/platform=watchOS Simulator' CODE_SIGNING_ALLOWED=NO build
xcodebuild -project iosApp/iosApp.xcodeproj -scheme iosApp -configuration Debug \
  -destination 'generic/platform=iOS Simulator' \
  LOKI_DESKTOP_ROOT=/absolute/path/to/LokiMetis CODE_SIGNING_ALLOWED=NO build
./gradlew :androidApp:assembleDebug -PlokiDesktopRoot=/absolute/path/to/LokiMetis
```

把示例中的桌面仓库路径替换为本机路径；完整的工具、签名和运行步骤见 [项目 README](../README.md#从源码运行)。图标母版是 `branding/app-icon.png`，在 macOS 仓库根目录执行 `swift scripts/generate_app_icons.swift` 可重新生成各端图标，只使用系统 SDK。

## 运行时文件布局（设备上）

知道数据落在哪里，排查缓存问题会快很多：

| 位置 | 内容 | 谁写 |
| --- | --- | --- |
| iPhone Keychain `…lan-identity-v1` | 本机设备 UUID | `DeviceIdentityStore` |
| iPhone Keychain `…lan-pairing-v1` | 每台桌面一条配对秘密，账户名为「桌面UUID.本机UUID」 | `PairingStore` |
| iPhone Keychain `LokiMetris.watch-http-revision.v1` | 下发给 Watch 的配置修订号（只增不减） | `PhoneWatchBridge` |
| iPhone `Application Support/lan-assets-v1/` | 按 SHA-256 命名的图片原文件 | `IOSAssetCache` |
| iPhone `Application Support/BackgroundRefresh/<本机UUID>.json` | 后台刷新目标（Bonjour 服务名） | `BackgroundTargetStore` |
| App Group `display-widget-v1.json` | 小组件摘要（含 45 秒租约） | App、小组件 |
| App Group `display-phone-v1.json` | 完整展示缓存（含图片清单，不含图片字节） | App、小组件 |
| App Group `display-widget-refresh-v1.json` | 只读 HTTP 目标 | App |
| App Group `Library/Caches/WidgetRefresh/*.json` | 每次 HTTP 刷新的诊断结果（不含地址与密钥） | 小组件、App 调试探针 |
