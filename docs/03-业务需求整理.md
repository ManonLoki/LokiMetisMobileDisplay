# 03 业务需求整理

> 上一篇：[02 技术架构](02-技术架构.md) ｜ 下一篇：[04 解决问题的思路与技术路线](04-问题与技术路线.md)

核对日期：2026-10-22；按 `codex/desktop-experimental` 工作树区分现有行为与体验目标；正式发布基线仍为 `v1.0.7`，Desktop 实验范围见 [11](11-Desktop实验展示终端.md)。主要 UI 图片、使用步骤见 [README](../README.md)，模拟器覆盖与未验证项见 [09](09-v1.0.6发布与UI验证.md)。

本篇整理当前产品需求：先说清楚产品是给谁、解决什么问题，再按端列出功能，最后是数据规则、时效、隐私和明确“不做”的部分。每条需求尽量注明它在架构里由谁实现，方便对照 [02 技术架构](02-技术架构.md)。原 README 的开发与验证记录保留在 [05 历史记录](05-历史开发与验证记录.md)。

## 一、产品定位

**用户**：同时使用多个 AI 编程工具（Codex、Claude Code、Cursor、Grok、WorkBuddy 等）的开发者。

**痛点**：想知道“今天用了多少 Token、各账户额度还剩多少、哪个 Agent 正在等我确认或出错了”，但不想一直盯着桌面窗口。

**方案**：桌面端负责统计，移动端做“副屏”——手机、平板放在桌边常亮显示，抬腕看手表，锁屏看小组件。移动端向桌面读取数据使用局域网连接，iPhone 与 Watch 之间使用系统配套通道；本项目不提供云端中转。桌面如何向上游工具统计或取额度由桌面项目负责。实验分支的 DesktopApp 也是展示终端，可放在电脑窗口中查看另一采集端的数据，UI 参照 Android 平板，不在本机重复采集。

## 二、核心场景

| 场景 | 期望 |
| --- | --- |
| 第一次使用 | 打开 App 自动发现同一 Wi-Fi 下的桌面，点“配对”，在桌面输入手机上的四位码，即可开始同步 |
| 日常使用 | 打开 App 自动连接已配对桌面，无需任何操作；切换菜单、改名称不会断开 |
| 手机放在桌边当副屏 | 用量数字实时更新，Hooks 状态和图片（含动图）随 Agent 活动变化 |
| 离开电脑 | iPhone／iPad、Watch 和小组件保留最近结果及原始时间；Android 主面板断线后清空，小组件单独保留摘要 |
| 抬腕查看 | 手表直接显示，手机不在前台也能取到最新缓存；手机不可达时手表自己向电脑取摘要 |
| 重装 App | Android 重新配对；iOS 沿用仍可读取的本机钥匙串身份与配对，缺失时重新配对 |

## 三、各端功能需求

### iPhone／iPad 主 App

**展示台**

- 两张卡片：**Token 用量**与 **Hooks**。按展示区域宽高选择上下或左右等分；只开一个时占满。用量可纵向滚动，Hooks 独立分页；两块都关闭时显示前往设置的空态。
- 用量卡片有**精简**与**详细**两档：
  - 精简：总量大字居中，下方小字保留完整整数；有额度时附各账户剩余额度。
  - 详细：每个 Agent 使用相同的两行样式——第一行名称、套餐小标签（Tag）与缩写总量，第二行左侧周期、剩余百分比与细进度条，右侧完整整数；只有额度的账户也使用此布局，不补造 Token 数字，Cursor 保留既有缺省 0。明细上方显示设备时区；完整整数在窄屏和大字号下可横向滚动查看。
- Hooks 有 **1×1**（每页一张）与 **2×2**（每页四张，不足留空位）两种布局，超过一页左右翻页。卡片只显示 Agent 名、状态和图片，点击看桌面下发的正文与大图；桌面已截断时明确显示“正文已截断”，不会恢复未传输内容。
- 断开、后台、重启后继续显示最近缓存，保留原采样与接收时间，连接信息在设置中查看；切换桌面或忘记配对后清空。

**设置**

- 桌面连接：发现列表、配对、连接、忘记；显示当前状态与上次同步时间。
- 面板：精简／详细、1×1／2×2、卡片开关，带布局示意，即时保存在本机。
- 本机：设备名称（共享 Kotlin 规则校验）、设备 ID。
- 扩展说明：Apple Watch 同步状态与重试；小组件添加方法与刷新说明。

**布局与适配**：紧凑宽度使用底部标签栏，常规宽度使用侧栏；iPad 分屏或窄窗口可能切回底部标签。展示台按可用区域宽高排布两张卡片，多窗口共用一条连接；大字号辅助模式下选项纵向排列、长数字横向滚动不截断。

### Apple Watch

- 三页水平分页：**Hooks ← Token → 额度**。首次打开停在 Token 页，之后记住最后所在页。
- Token 页固定精简：总量缩写、完整整数、统计日期。
- Hooks 页每屏一张卡片，上下滚动或转表冠吸附切换；顶部一行显示 Agent 与状态，其余空间显示图片；不展示正文，没有详情或点击跳转。
- 额度页：账户类型、套餐小标签与各周期剩余额度、细进度条；同一账户的多个周期通常同行等分，大字号辅助模式下纵向排列。
- 没有应用内设置、配对或手动同步入口——自动沿用系统已配对的 iPhone。
- 支持 Always On：低亮度时继续显示缓存，停止动画。
- 后台刷新以展示数据为主，缺失的新图片在手表回到前台后继续通过手机同步。

### 小组件

- 桌面：小号、中号；锁屏：单行、圆形、矩形。
- 按尺寸选择显示总量、额度、Hooks 摘要与**上次同步时间**：桌面尺寸可列最多四个账户的实际窗口，锁屏尺寸按空间展示精简信息，不能要求单行或圆形布局同时容纳全部内容。
- 从未同步显示空态，不显示 0；断线不伪装在线。

### Android（对照）

共享用量／Hooks 主面板与设置能力，另有：桌面小组件（可调整尺寸、刷新按钮）、可拖动的紧凑悬浮窗（Token 与 Hooks 两页，在内容区左右滑动，或点击标题、内容切换，拖动标题移动窗口）、可选的“后台实时同步”前台服务。悬浮窗 Token 页显示完整整数总量及最多四个额度账户，Hooks 页最多四条，超出时提示打开 App 查看；没有纵向滚动。关闭窗口后后台实时同步服务继续；锁屏或息屏时隐藏窗口，解锁后恢复原本开启的窗口。完整主面板快照只在当前连接内存中，断线即清空；合法实时快照另持久化裁剪的小组件摘要，不恢复主面板。宽窗口使用侧边导航栏，窄窗口使用底部导航。

### Desktop 实验展示终端

- 与 Android 平板共用 Compose 展示台和设置：宽窗口侧栏、用量与 Hooks 左右分区；窄窗口底栏、上下分区；保留 Token 精简／详细、Hooks 1×1／2×2、图文详情和设备设置。
- 鼠标可直接点击“上一页／下一页”切换 Hooks；点击卡片打开正文和大图详情。图片支持 BMP、PNG、JPEG、WebP、GIF，动图保留帧时长与循环次数。
- 自动发现采集端，用户明确选择后打开四位码配对窗口；已配对来源自动重连。修改设备名和面板选项只改本机偏好，不重启连接。
- 窗口存续期间持续连接，失焦与最小化不关闭网络；最小化暂停界面动效，关闭窗口退出。断线即撤下完整展示数据，重启不恢复旧面板；已校验图片仅在新认证快照再次引用后复用。
- 为兼容现有采集端，按 Android 平板协议身份连接；采集端列表显示为 Android 平板，本机实际仍是桌面 JVM 应用。
- 没有 Android 系统悬浮窗、小组件、后台服务开关或 Apple Watch 通道；不采集本机 Token，不修改采集端正文、图片或 Agent 开关。Windows／Linux 构建配置待验证，本次已验证 macOS arm64。

## 四、数据显示规则

| 规则 | 说明 |
| --- | --- |
| 数字格式 | 主数字用 K／M／B 近似（最多两位小数），下方小字保留完整整数；完整整数不经浮点转换 |
| 统计质量 | 保留“部分／估算”等质量字段；不绘制对应视觉标签，辅助功能／读屏描述仍可披露统计质量 |
| 额度窗口 | 统一称“每月、每周、5h”，按此顺序；缺失的窗口直接隐藏，不补占位；余额为 0 显示 0% |
| 额度来源 | 由桌面提供 Codex、Claude、Cursor、Grok 的实际窗口；常见来源为 Cursor 每月、其他账户每周与 5h。终端按下发字段展示，不自行补窗口或根据 Token 推算 |
| 用量面板样式 | 各 Agent 名称、周期与百分比使用相同字级；周期使用次要文字色，百分比与条按剩余比例着色：不超过 20% 为红色、不超过 50% 为黄色，其余为绿色。同一详细面板的短条等宽，精简模式共用全宽条；所有条连续填充，不带末端圆点或间隙。重置时间保留给读屏，额度更新时间仅显示一次 |
| 账户排序 | Codex、Claude Code、Cursor、Grok、其他，WorkBuddy 固定最后 |
| 套餐标识 | 使用桌面提供的套餐信息，在账户或 Agent 名称后显示小号 Tag，例如 `Cursor [Ultra]`、`Codex [Pro]`，与相邻文字底部对齐；同排 Hooks 状态 Tag 也采用底部对齐 |
| Agent 开关 | 用量明细与额度跟随桌面设置的启用名单；例如只开启 Codex 与 Cursor 时不显示其他 Agent。名单随快照、缓存、HTTP 摘要和 Watch 同步；旧桌面未提供名单时保留原展示行为 |
| Cursor 缺省 | Cursor 已开启且缺少 Token 数据时显示 0；关闭时不补占位。默认值只用于展示，不写回数据 |
| Hooks 状态 | 运行、询问（等待确认）、出错、空闲四态，各有固定颜色 |
| 图片格式 | BMP、PNG、JPEG、WebP、GIF；动图保留原始帧时长与循环次数 |
| Agent 名称 | 共享别名映射覆盖 Codex、Claude Code、Cursor、Grok、WorkBuddy、OpenCode、Hermes、OpenClaw、CodeBuddy、Qwen Code、Kimi Code、Qoder、Gemini CLI、GitHub Copilot；未知自定义名称原样保留 |

## 五、连接、时效与离线

| 需求 | 实现要点 |
| --- | --- |
| 前台自动发现，无“开始／停止”开关 | 共享 `TerminalConnectionPolicy.enterForeground`，平台执行发现与连接；Desktop 启动后在窗口存续期持续连接 |
| 首次配对必须由用户选择桌面 | 自动选择只针对已保存配对的候选 |
| 收到第一份真实快照才显示“已连接” | 广告和握手成功都不算在线 |
| 后台暂停、回前台自动恢复 | 普通模式退后台尽力发送加密 `pause` 后关闭；Android 显式开启后台实时同步时由前台服务继续接收 |
| Desktop 失焦／最小化 | 保留网络连接；最小化暂停动画，关闭窗口退出，断线清空完整面板 |
| 断线自动重连但有上限 | 最多 8 次，退避 0.5～8 秒；所选实际端点／网络变化、成功快照、回前台或用户重试可重置预算。同一端点的重复广告不续预算 |
| 离线展示保留真实采样时间 | 缓存永远带原始接收时间，不能因为“读到了缓存”而刷新时间 |
| Apple 后台申请 5 分钟 | iPhone 后台、小组件 Timeline、Watch 后台都申请 5 分钟；实际由系统调度，**不承诺准点** |
| Android 普通后台申请 15 分钟 | `JobScheduler` 拉取只读摘要；可手动立即同步，也可显式开启有持续通知的后台实时同步 |
| Watch 不依赖手机前台 | 手机后台也能回复缓存；不可达时 Watch 直接 HTTP |

## 六、安全与隐私

- 主连接与只读摘要端点限制在局域网／本机地址，iPhone 与 Watch 走系统配套通道；移动项目不提供云推送或自建上传服务。
- Apple 主连接的配对秘密只在 iPhone／iPad 私有 Keychain（不同步、不进 App Group、不进日志）；Android 用本机 Keystore 密钥加密保存。
- 小组件和 Watch 的独立 HTTP 密钥仅能读取摘要；主配对秘密不下发。Watch 另可通过 iPhone 收取完整快照和图片，界面只展示状态与图片。切桌面、忘记配对会撤销本机读取配置并发布 Watch 撤销修订；离线 Watch 实际收到撤销依赖系统送达，旧消息不能恢复已接纳的撤销。

## 七、体验要求

- 深色赛博主题：冷青与紫色光边、细网格、局部扫光、分层入场、数值滚动过渡。
- 所有持续动画只在“前台 + 当前页面 + 可见”时运行；响应系统“减弱动态效果”；Watch 低亮度时停止。
- 读屏标签完整：数字读完整值，额度读窗口、百分比与重置时间。
- **省电目标与实现**：投影相同时不主动投递主线程更新，装饰动画降低刷新频率，后台任务完成后结束；这不能保证 SwiftUI 本身绝不重算，也不是耗电实测结论。历史排查见 [04 · 性能与耗电优化](04-问题与技术路线.md#四本轮-ioswatch-性能与耗电优化)。

## 八、明确不做／不承诺

- 不保证息屏或后台准点更新——系统后台调度、低电量模式、厂商策略都会推迟。
- 不提供云同步、APNs 推送或面向公网的桌面连接；系统配套通道的实际传输由 Apple 管理。
- Watch 不独立配对桌面，不建立自己的 TCP 长连接。
- 不根据 Token 估算额度，不显示上游没有提供的窗口。
- 构建、模拟器与测试数据验证不等于真机互通验收；版本发布说明应明确区分验证范围，已有记录见 [05 历史记录](05-历史开发与验证记录.md)。
