# 06 发布检查清单

> 回到 [项目说明](../README.md) ｜ [文档索引](README.md)

**每次发布版本，包括补丁版，都必须核对 README。** 在创建发布标签、发布安装包前完成；文档核对属于发布完成条件。仓库中的长期执行规则见 [AGENTS.md](../AGENTS.md)。

## 按当前代码逐项核对

- [ ] **安装与启动调试**：下载或签名安装方式、开发工具要求、桌面源码依赖、路径设置、构建／安装／启动／测试命令仍可用。
- [ ] **已有能力**：新增、修改、移除的能力已反映在 README；各平台的差异、后台更新与离线行为描述准确。
- [ ] **设备范围**：设备类型、最低系统、CPU 架构，以及 Watch 与手机的关系符合构建配置。
- [ ] **文件结构**：目录和入口没有失效，新人能找到要改的模块。
- [ ] **项目架构**：各端使用的技术、模块责任、数据流、外部 Rust 核心与缓存关系符合实现。
- [ ] **关联文档**：同步受影响的 `docs/`，检查本地链接；README 保持为当前入口，历史记录保留在历史文档或版本说明中。

## 把核对结果写进本次发布记录

- [ ] 从 [Android 配置](../androidApp/build.gradle.kts) 核对 `versionName`／`versionCode`，从 [Apple 配置](../iosApp/Configuration/Config.xcconfig) 核对 `MARKETING_VERSION`／`CURRENT_PROJECT_VERSION`，确认各端实际产物版本；各平台构建号分别记录。
- [ ] 记录编译使用的桌面仓库提交，以及本次提供的安装产物、签名安装方式和校验文件。
- [ ] 记录 README 已核对、改了哪些部分；无需修改的部分也注明已核对。
- [ ] 记录实际执行的构建、测试和设备验证。区分编译通过、模拟器检查、真机安装和真实数据互通；Watch 安装状态单独记录。

可在发布说明中使用下面的简短格式：

```text
文档核对：已按当前代码检查安装调试、能力、设备、目录与架构；本次更新……
版本：Android <版本名 / 构建号>；Apple <版本名 / 构建号>
桌面 Rust 源码：<提交 SHA>
产物与安装：<APK、校验文件、Apple 签名安装范围等>
验证：<实际完成的检查，以及未验证的范围>
```

核对后内容仍准确时，保留原文并记录依据即可。后续若代码变化影响上述说明，应在发布前重新核对相应部分。
